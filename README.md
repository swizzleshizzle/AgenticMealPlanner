# Agentic Meal Planner

A self-hosted web app for running your own meal-kit operation — recipe library, weekly meal planning, pantry tracking, grocery shopping lists, and receipt logging — with an AI assistant that can read and edit your plan in plain language.

It was built to replace a meal-kit subscription: keep the recipes you like, plan a week of batch-prep and fresh-cooked dinners, auto-generate the shopping list from what you already have, and push the schedule to your calendar.

> [!IMPORTANT]
> This app ships with **no authentication**. It is designed to run on a trusted private network (LAN or a [Tailscale](https://tailscale.com/) tailnet), not on the public internet. Read [`SECURITY.md`](SECURITY.md) before deploying anywhere reachable.

---

## Features

- **Recipe library** — import recipes from a PDF or photo (parsed by Claude), or enter them by hand. Recipes support **variants** (alternate versions of the same dish) and **archiving**, with full version history.
- **Weekly planner** — Sunday-anchored weeks with per-day, per-slot meals. Each planned meal has a **cook style**: cook fresh, batch prep, or leftovers. Scale servings per meal.
- **Per-batch pantry** — track ingredients as individual batches with their own unit, location (fridge / freezer / pantry), expiration date, purchase date, and cost. Mark a meal "cooked" and the app deducts the right batches, flagging any shortfalls.
- **Shopping list** — auto-generated by diffing a plan's required ingredients against what's on hand, with support for ad-hoc custom items.
- **Receipt tracking** — log grocery trips by paste, photo, or PDF; Claude parses line items, matches them to known ingredients, and can stock the pantry from them.
- **Ingredient normalization** — aliases and unit conversion (weight/volume/count) so "scallions" and "green onions" resolve to the same thing.
- **AI chat assistant** — a Claude agent with tools to read and mutate your plan, pantry, recipes, and shopping list. Ask it to swap a meal, scale prep, plan a whole week, or tell you what you can cook from what's in the fridge.
- **Google Calendar integration** (optional) — push confirmed meals to your calendar via OAuth2.

## Architecture

```
AgenticMealPlanner/
├── client/                  # React + Vite SPA
│   └── src/
│       ├── pages/           # Dashboard, Recipes, Planner, Pantry, Shopping, Chat
│       ├── components/      # UI, cook-confirm modal, pantry drawer, chat
│       └── api/             # typed fetch wrappers over the REST API
├── server/                  # Express + Prisma API
│   └── src/
│       ├── routes/          # REST endpoints (see API surface below)
│       ├── services/        # planning, pantry, shopping, receipts, media, calendar
│       ├── agent/           # Claude agent: runner, tool registry, system prompt
│       ├── claude/          # recipe/receipt parsers, planner, SDK client
│       ├── jobs/            # scheduled jobs (nightly pantry purge)
│       └── prisma/          # schema, migrations, seed
└── docker-compose.yml       # local Postgres
```

The client is a single-page app that talks to the server over a small REST API (all routes under `/api`). The server owns all business logic and is the only thing that talks to the database, to Claude, and to Google.

### The AI agent

The chat assistant runs on the Claude Agent SDK. It's given a system prompt with the current date, the active week, and what page the user is looking at, plus a registry of tools it can call:

- **Read tools** — `get_pantry`, `get_planned_week`, `get_meals`, `get_meal_detail`, `get_shopping_list`, `get_recent_receipts`
- **Action tools** — `add_planned_meal`, `swap_meal`, `skip_meal`, `scale_servings`, `mark_meal_cooked`, `remove_planned_meal`, `set_plan_status`, `generate_full_week`, `add_pantry_batch`, `update_pantry_batch`, `consume_pantry_batch`, `delete_pantry_batch`, `create_recipe_version`, `archive_meal`, `unarchive_meal`, plus recipe / shopping / receipt tools.

Destructive or hard-to-undo actions are confirmed with the user before the agent runs them.

### API surface

All endpoints are unauthenticated and mounted under these prefixes:

| Prefix              | Responsibility |
|---------------------|----------------|
| `/api/health`       | Liveness check |
| `/api/ingredients`  | Ingredient catalog, aliases, resolution |
| `/api/meals`        | Recipes, variants, versions |
| `/api/pantry`       | Pantry batches |
| `/api/plans`        | Weekly plans and planned meals |
| `/api/shopping`     | Shopping lists (generated + custom items) |
| `/api/chat`         | Agent chat (server-sent events) |
| `/api/calendar`     | Google Calendar OAuth + sync |
| `/api/receipts`     | Receipt upload and parsing |
| `/media`            | Uploaded images and recipe assets |

## Getting started

### Prerequisites

- **Node.js 20+** and npm
- **Docker** (for the bundled Postgres), or your own PostgreSQL 16 instance
- **Claude credentials** for the AI features — either run `claude login` once on the host (the SDK reads `~/.claude/.credentials.json`) or set `ANTHROPIC_API_KEY`. **Usage is billed to whoever's credentials these are.**
- **poppler-utils** (`pdfimages`, `pdftoppm`) — *optional*; needed only for extracting thumbnail images from imported recipe PDFs. The app boots and runs without it (thumbnail extraction is just disabled).
- **Google OAuth credentials** — *optional*; only if you want calendar sync.

### 1. Install

```bash
git clone <your-fork-url> AgenticMealPlanner
cd AgenticMealPlanner
npm install        # installs both workspaces
```

### 2. Start Postgres

```bash
docker compose up -d
```

This brings up Postgres 16 on host port **5433**. (The default password in `docker-compose.yml` is for local development only — rotate it for any non-localhost use. See [`SECURITY.md`](SECURITY.md).)

### 3. Configure the server

```bash
cp server/.env.example server/.env
```

Then edit `server/.env`:

```dotenv
DATABASE_URL="postgresql://mealplanner:mealplanner@localhost:5433/mealplanner?schema=public"

# Optional — Google Calendar sync
GOOGLE_CLIENT_ID=your_client_id_here
GOOGLE_CLIENT_SECRET=your_client_secret_here
GOOGLE_REDIRECT_URI=http://localhost:3001/api/calendar/callback

# Optional — only if you aren't using `claude login` on the host
# ANTHROPIC_API_KEY=sk-ant-...
```

> [!NOTE]
> The Vite dev server proxies API calls to **port 3100**, while the server defaults to **3001**. For the default dev setup to work end-to-end, set `PORT=3100` in `server/.env` (or adjust the proxy target in `client/vite.config.ts` to match your server port).

### 4. Set up the database

```bash
npm run db:migrate --workspace=server   # apply schema
npm run db:seed --workspace=server      # optional: seed common ingredients
```

### 5. Run it

```bash
npm run dev
```

This starts the API and the client together (via `concurrently`):

- Client (Vite): http://localhost:5173
- API (Express): http://localhost:3100 (or `PORT` from your `.env`)

## Common commands

Run from the repo root:

| Command | What it does |
|---------|--------------|
| `npm run dev` | Run client + server together |
| `npm run dev:server` | Server only |
| `npm run dev:client` | Client only |

Run with `--workspace=server`:

| Command | What it does |
|---------|--------------|
| `npm run build --workspace=server` | Compile the server (`tsc`) |
| `npm run start --workspace=server` | Run the compiled server |
| `npm run test --workspace=server` | Run the Vitest suite |
| `npm run db:migrate --workspace=server` | Apply Prisma migrations |
| `npm run db:push --workspace=server` | Push schema without a migration |
| `npm run db:seed --workspace=server` | Seed common ingredients |

Run with `--workspace=client`:

| Command | What it does |
|---------|--------------|
| `npm run build --workspace=client` | Type-check and build the client |
| `npm run preview --workspace=client` | Preview the production build |

### Background jobs

The server schedules a nightly job (03:00 server time) that purges pantry batches consumed more than 30 days ago. It runs automatically when the server is started normally and is skipped during tests.

## Deployment notes

This app is meant to run on a host you control, reachable only over a trusted network:

- Bind the server to `127.0.0.1` or your tailnet interface rather than `0.0.0.0` where possible.
- Put an authenticating proxy in front of it (Tailscale, Cloudflare Tunnel + Access, oauth2-proxy, or similar) if anything but you can reach it.
- Rotate the local-dev Postgres password and keep `server/.env` and `calendar-tokens.json` out of version control (they are gitignored).

The full threat model and hardening guidance live in [`SECURITY.md`](SECURITY.md). **Read it before exposing this beyond localhost.**
